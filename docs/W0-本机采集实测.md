# W0 · Windows 采集能力本机实测笔记

> 实测时间：2026-09-16 22:15–22:30。机型：**Lenovo Legion 82TF**（i5-12500H，16 逻辑核 / 12 物理核，39.8GB，RTX 3050 Ti Laptop，Samsung SSD ×2）
> 系统：**Windows 11 专业版 10.0.26200**，显示缩放 **150%**，单显示器。
> 探测脚本：`probe/w0-probe.ps1`（广度）、`w0-probe2.ps1`（定向）、`w0-probe3.ps1`（负载交叉验证）、`sensor-probe/`（Rust sysinfo）。原始输出见同目录 `w0-output*.txt`。
> 结论用途：修正《WinGauge-产品规划.md》第五/八节的技术假设。**规划里被实测推翻的地方，见第三节。**

## 〇、最重要的三条结论

1. **通用（跨品牌）温度通路确认不可靠，但厂商通路可用。** `MSAcpi_ThermalZoneTemperature` 在本机恒返回 `2732`（0.1°C），空载/满载/撤载三点完全不变 —— 固件未实现。`sysinfo` 在 Windows 上的温度实现走的就是这个类（`src/windows/component.rs:260`），实测返回 **`label="Computer" temp=Some(-0.15°C) max=Some(-0.15)`** —— 负温度、且是 `Some`。**任何 `Option` 有值就渲染的 UI 都会显示 "-0.1°C"。** 必须做合理性校验。
2. **⚠ 本条为第四轮补测结论，推翻第三轮的误判：本机联想 EC 通路可以读到真实风扇转速与温度。**
   - 误判原因：第三轮用了错误的类（`LENOVO_GAMEZONE_DATA`，其 `GetCPUTemp` 确实恒返回 `Data:0`）且**漏传 in 参数**，把"调用方式不对"当成了"硬件读不到"。
   - 正确通路：`root\wmi\LENOVO_FAN_METHOD`，**必须带 `FanID` / `SensorID` 入参**。
     - `Fan_GetCurrentFanSpeed(FanID=0/1)` → **2464–2833 RPM**，两个风扇，连续 6 次快读有 ±20 抖动，是真实转速而非固定值。
     - `Fan_GetCurrentSensorTemperature(SensorID=3)` → **73–79°C**（随时间变化，判定为 CPU 侧）。
     - `Fan_GetCurrentSensorTemperature(SensorID=4)` → **51/52°C**，与 `nvidia-smi` 同时刻读数**逐格完全一致** → 确认 SensorID 4 = GPU 温度。**这是本笔记里唯一一条被独立信源交叉验证过的读数。**
   - 不可用的部分：`SensorID 0,1,2,5..12` 全部"无效的对象"；`Fan_Get_Table` 返回空；`LENOVO_GAMEZONE_DATA` 全系方法在本机死路。
   - **含义**：温度/风扇不是"平台性不可得"，而是"**必须有厂商专用 provider + 首次运行扫描 SensorID/FanID 并交叉验证**"。详见第五节。
3. **慢的是 WMI 通路，不是采集本身。** PowerShell + WMI 单次查询实测 0.3–3s（设备信息 1747ms、`Get-PhysicalDisk` 3023ms），**但 `sysinfo` 的原生通路实测 `refresh_cpu_all=0ms`、`refresh_memory=0ms`、磁盘枚举 2.1ms、网络 refresh 25ms** —— 1 秒采样回路完全够用。分工定案：**实时层 = sysinfo/原生 API；WMI 只用于启动时一次性静态信息（机型、CPU 名、物理核数）与低频健康检查。** 注意 `System::new_all()` 冷启动 1.8s，必须按需用 `RefreshKind` 并用后台线程，否则拖慢首屏。

## 二、意外发现（规划里没写到的）

1. **PDH 英文计数器路径在 zh-CN 系统上直接可用** —— `Get-Counter '\Processor Information(_Total)\% Processor Time'` 返回 27.9。原规划把"计数器名本地化"列成了风险，**可以降级**：PDH 有英文/本地化双名表，按英文名请求即可。（Rust 侧 `pdh` crate 同理。）
2. **本机 UAC 已关闭（`EnableLUA=0`），所有进程天然带管理员权限。** 这意味着上表所有 ✅ **都无法区分"普通权限可读"还是"因为管理员才可读"**。规划里"绝不要求管理员权限"这条红线，必须在另一台开着 UAC 的普通机器上重跑一遍 `w0-probe.ps1` 才算验证。**这是 W0 唯一没闭环的项。**
3. **网络接口环境比预想脏得多**：11 个适配器，含 VMware ×2、Hyper-V 虚拟交换机 ×2、OpenVPN ×2、Sangfor SSL VPN、Wi-Fi Direct 虚拟卡、蓝牙 PAN。`Win32_PerfFormattedData_Tcpip_NetworkInterface` 把名字规范化到失真（`Intel[R] Wi-Fi...`、`Realtek USB GbE` → 同时出现 `Realtek USB FE` 变体），且**无 ifIndex**。→ 主接口选择必须是"默认路由 ifIndex → IP Helper 按 ifIndex 取计数"，**不能按名字匹配**。规划 R7 的对策要按此收紧。
4. **`Get-NetAdapterStatistics` 没有 ifIndex 属性**（表格里整列空白），只能按 Name 关联 —— 又一个不能靠名字的证据。
5. **SSD 寿命（Wear）读不出来**，只有温度。参考图磁盘卡片那个"正常"标签，本机只能靠 `HealthStatus`（Get-PhysicalDisk）给，而它耗时 3 秒 → 磁盘健康必须低频缓存，不能实时算。
6. **"交换"在 Windows 上有两套完全不同的语义，数字差一个数量级。** 同一时刻：`sysinfo` 报 `swap total=35.2GB used=10.2GB`（这是**提交内存**超出物理内存的部分，源自 `GlobalMemoryStatusEx` 的 PageFile 字段），而 `Win32_PageFileUsage.CurrentUsage` 报 **295MB**（这是 pagefile.sys 实际占用）。参考图那行写的是 `交换 7.0 GB`。**必须选一个并在 UI 文案上说清楚**，否则用户看到"交换 10GB"会以为机器出问题了。建议：显示 `已提交 X / Y GB`，不出现"交换"字样。
7. **PDH 的 PhysicalDisk 实例名不能靠盘符拼。** 实测本机实例名是 `0 C: G:` 和 `1 E: F:`（一块盘挂多个卷），`\PhysicalDisk(0 C:)\...` 直接报"计数器路径无效"。→ 必须先枚举实例再匹配，或走 `\LogicalDisk(C:)`（该路径实测可用）。
8. **sysinfo 的网络接口名是友好名（`以太网 3`、`本地连接* 2`），比 WMI 性能类的名子干净得多，但不暴露 ifIndex**，且会混进 `本地连接* 2-Native WiFi Filter Driver-0000` 这类派生条目。→ 主接口判定若走 ifIndex（默认路由），需要用 IP Helper `GetAdaptersAddresses` 做一次 ifIndex↔FriendlyName 映射；纯 sysinfo 不够。

### 方法论教训（写下来，防止再犯）

1. **"WMI 方法调用失败" 的第一嫌疑是调用方式，不是硬件不支持。** 本轮三种失败各有不同成因：漏传 in 参数（`无效的参数`）、类选错（GAMEZONE vs FAN_METHOD）、该 SensorID 在本机不存在（`无效的对象`）。把它们笼统归成"读不到"是错的。
2. **必须先看 `Get-CimClass` 的 `CimClassMethods.Parameters`，再决定怎么调。** 上一轮只列了方法名没列参数，直接导致了误判。
3. **凡是传感器读数，未经交叉验证不下结论。** 本轮唯一"确认可信"的是 SensorID 4，因为它和 `nvidia-smi` 逐格吻合。判定链应是：有独立信源比对 > 加负载看是否变化 > 恒定值即判无效。
4. **PowerShell 侧的坑（本机踩了三次）**：`$Args` 是自动变量不能作参数名；`R` 是 `Invoke-History` 别名不能作函数名；`.ps1` 必须 UTF-8 **带 BOM**。

### 对本产品的落地要求

- 温度/风扇改为 **`thermal::lenovo` provider**（厂商扩展位），不是全局能力，只在探测到 `root\wmi\LENOVO_FAN_METHOD` 实例时启用。
- **首次运行必须做 SensorID/FanID 扫描**（FanID 0..3、SensorID 0..12），把成功的 ID 与角色（CPU/GPU/未知）写入 `config.toml`，而不是硬编码 3 和 4。
- 角色识别用交叉验证：若能读到 NVML 温度，则与某个 SensorID 逐次比对，相等即标为 GPU；其余变化的标为 CPU/未知，UI 上宁可写"传感器 3"也不要乱贴标签。
- **非联想机型仍按"读不到"处理**（卡片消失），这条不变。

## 六、复现方式

```bash
# 三个 PowerShell 探测（第三轮会制造 25 秒 CPU 负载）
powershell -NoProfile -ExecutionPolicy Bypass -File probe/w0-probe.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File probe/w0-probe2.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File probe/w0-probe3.ps1   # ⚠ 结论已被第四轮推翻
powershell -NoProfile -ExecutionPolicy Bypass -File probe/w0-probe4-lenovo.ps1  # 带正确入参的联想 EC 补测
# 分节执行：-Section thermal,fan,disk
cargo run -p sensor-probe          # Rust sysinfo 通路实测
```

> 脚本必须存为 **UTF-8 with BOM**：Windows PowerShell 5.1 无 BOM 时按 GBK 解析，中文字符串会导致语法错误（本次已踩到）。

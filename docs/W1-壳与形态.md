### 3. 关键设计落地

- **Capability 权限最小化**：`capabilities/default.json` 只声明面板需要的 12 条权限，不图省事用 `core:default` 全开。
- **窗口关闭用 `hide()` 不用 `destroy()`**：重新打开瞬间有数据（W3 趋势线不断的前提）。
- **`tray-icon` feature 显式开启**：Tauri 2.11 默认不编入托盘模块，必须 `features = ["tray-icon", "image-png"]`。
- **`listen` 闭包签名**：2.11 是 `Fn(Event)` 单参数（不是旧文档的 `|window, event|`），窗口引用从外部捕获。
- **`PhysicalRect` 无构造函数**：字段 `position`/`size` 是 `pub`，直接字面量构造；托盘事件的 `Rect` 是 `Position`/`Size` 枚举，需手动转物理值。

## 三、遗留项（W1 未完全闭环）

1. **失焦自动收起未能在脚本环境验证**。
   原因不是代码问题：当前会话无法获得 Windows 前台权限（`SetForegroundWindow` / `AttachThreadInput` / cua-driver click 全部被前台锁定拒绝，`foreground_unavailable: Windows did not activate exact target`），因此无法制造真实的 `WindowEvent::Focused(false)`。
   **需要在真实用户交互下复测**：打开面板 → 点别处 → 面板应 150ms 后消失。若不消失，查 `on_window_event` 的 Focused 分支与 `is_focused()` 复查逻辑。

2. **钉住拖动未端到端验证**（同上原因，无法让面板获得焦点以触发拖拽）。

> **修订（2026-09-17）**：
> 1. **图钉无效**：根因是前端 `togglePin()` 只改了本地 `pinned` ref，**没有 emit `panel/pin` 事件给 Rust 侧**，导致 `PanelState.pinned` 恒为 false，钉住后照样被失焦收起。这是典型的"前后端状态分裂"——钉住是跨进程共享状态，单边修改必然失效。
> 2. **拖动完全不动**：真正根因是事件名 `dragstart` 与 **DOM 原生保留事件冲突**——Vue 的 `@dragstart` 会被当作 HTML5 拖拽事件处理，自定义组件事件永不触发，`startDrag` 一次都没被调用。改名 `header-mousedown` 后修复。
>    （此前诊断的卡顿/漂移问题也一并修了：每帧 `await panel.emit` 改为不 await；前端不再用 `screenX - clientX` 推算窗口原点，改为只发增量位移 `panel/drag-delta`，由 Rust 侧 `outer_position()` 叠加并 `clamp` 进工作区。）
> **教训**：自定义事件名不要用 DOM 保留字（dragstart / click / focus / submit…），否则 Vue 会按原生事件处理，且失败方式是"静默不触发"，极难排查。
>
> **再修订（2026-09-17 下午）**：
> 3. **自绘 drag-delta 仍不丝滑、且无法跨屏**。根因：mousemove → IPC → Rust set_position 往返延迟；`current_monitor()` 的 work_area clamp 把窗口锁死在当前屏。**废弃 drag-delta**，改为调用系统原生 `webviewWindow.startDragging()`（权限 `core:window:allow-start-dragging`）。位置记忆改挂 `WindowEvent::Moved`。原生拖动由 OS 合成，丝滑且可跨显示器。
> **教训**：Windows 无边框窗口拖动优先走系统 `WM_NCHITTEST`/`startDragging` 路径，不要自己模拟。

3. **托盘左键单击未端到端验证**。Win11 托盘是 XAML Island，无可编程按钮句柄；`smoke_show_panel` 调试命令已加（模拟右下角托盘 rect），但真实点击需人工执行。

4. **多显示器/DPI 仅逻辑覆盖**：定位算法读了 `current_monitor().work_area()`，但本机单显示器 + 150% 缩放，多屏回弹分支未实测。

## 四、对 W2 的接口约定

- `wingauge-core::Snapshot` 已定义好（CPU/内存/网络/磁盘四类，全部 `Option` 包裹，读不到即 None）。
- 推送通道：Rust 侧 `emit("snapshot://tick", snapshot)`，前端 `listen`。W1 已预留事件名，W2 填充 provider 后即可联通。
- Provider 契约：`Provider::probe() -> Capability { Available, Degraded, Unavailable }`。**读不到的卡片整卡隐藏，不显示 0 / N/A** —— 这是验收清单的硬条款。
- 温度/风扇卡片是厂商 provider 能力（联想先行），W2 的 provider 抽象要为此留扩展位。
